# Deployment

## Local demo

Use Node 22 LTS. The project currently has no runtime package dependencies.

```sh
npm ci
npm run dev
npm test
npm run build
npm run build:gas
npm run doctor
```

The local demo uses synthetic defaults and browser storage. Its banner identifies it as `DEMO / LOCAL`; it is not connected to Google and does not send content to AI.

## Apps Script staging

`deploy/gas/` is generated by `npm run build:gas`. It intentionally contains no `.clasp.json`, Script ID, account credentials, or production settings. The current staging installation uses the user's existing legacy Spreadsheet and Drive folder temporarily, as explicitly requested; this is not an acceptable production layout. Before production, create a separate backup root and independent Apps Script/Spreadsheet/Drive resources. Configure `APP_ENV=staging`, `WORKSPACE_ID`, `SPREADSHEET_ID`, `DRIVE_ROOT_ID`, `BACKUP_ROOT_ID`, `ALLOWED_DOMAIN`, `BOOTSTRAP_ADMIN_EMAIL`, `SCHEMA_VERSION=1`, and `AI_ENABLED=false` in Script Properties.

Install the locked clasp tool in the project before using it; clasp is not currently installed or locked in this repository. Link only the staging project, verify `rootDir` is `deploy/gas`, enable the Apps Script API and Sheets Advanced Service, then inspect the generated manifest and run the private `initializeWorkspace_` setup from the editor. Deploy a test Web App as the maintainer and limit access to the confirmed domain. Do not point this package at an existing or production Apps Script project.

The generated project now includes protected document workflows, payments/reversals, receipts, master data, users/settings, jobs, migration preview/commit, backup manifests, and private Drive file indexing/upload/download. PDF rendering is still a staging proof requirement, and the endpoint in the legacy browser app is not a staging target; the official page is the Apps Script HtmlService page using `google.script.run`.

## Required staging order

1. Create a new staging Workspace Spreadsheet, Drive root, backup root, and standalone Apps Script project. Do not reuse production resources.
2. Confirm the Workspace domain and provide one maintainer, two ordinary members, and one non-member test account. The accounts must be able to sign in to the Web App.
3. Enable Apps Script API and Sheets Advanced Service for the staging project. Review `deploy/gas/appsscript.json` scopes before authorization.
4. Set Script Properties from `.env.example`, replacing every blank placeholder. Do not place secrets in the repository.
5. Run `initializeWorkspace_` once from the Apps Script editor as the maintainer. Confirm all schema tabs exist and the bootstrap Admin row is present.
6. Deploy a Web App as the maintainer, restricted to the confirmed Workspace domain. Record deployment version and URL.
7. Run identity checks: owner, two members, non-member, and a case where active-user email is unavailable. The last two must be denied.
8. Test the business sample: quotation -> approval -> issue -> invoice 1000 -> payments 300 and 700 -> two receipts -> dashboard month totals.
9. Test file upload/download with synthetic PNG/PDF files and verify no public sharing. Test backup manifest creation and migration preview in staging.
10. Only after staging acceptance should a separate production project and resources be created. Production deployment and data import remain manual approvals.
